# Production Operations — 生产运营限界上下文

> 本文描述当前生产运营。保存、恢复与管理命令见[当前运行合同](current-runtime.md)，旧设计和实施记录见 [ADR-PO-02](../../architecture/adr/ADR-PO-02.md)。

## 1. 领域定位

Production Operations 负责 Victoria Economics 中生产建筑的生产方案管理、配方解析、生产批次组织、实际参产人员安排、生产进度推进和生产结果结算的业务协调。

本上下文以经济建筑作为生产活动的业务载体，但建筑身份、库存、任职、工资与资金分别由其他上下文管理。

当前生产采用双聚合方案。`EconomicBuilding` 持有身份、类型和运营状态，两个生产聚合以 `buildingId` 关联并各自通过独立 Repository 保存。

## 2. 权威事实

Production Operations 是以下事实的权威来源：

- 每栋生产建筑当前有效的 Production Method 组合。
- 当前唯一待生效的生产方案目标。
- 当前配方所需的原料、产品及职业满配需求。
- 当前生产批次的身份、配置快照、参产人员、进度和生命周期。
- 批次的结算决定，包括正常完工的全额耗料和产出，以及特殊中止的全额退款和零产出。
- 当前批次冻结的整数参产人员及比例速度。
- 实际参产状态及其发生变化的时间事实。

## 3. 聚合与不变量

### ProductionMethodConfiguration

保护有效生产方法组合始终合法，并管理最多一个 Pending 目标。

运行中的生产批次不受后续方法选择变更影响。

`configurationRevision` 随实际配置变化递增，包含 Pending 新增、替换和取消；`effectiveRevision` 仅在有效组合真正改变时递增。是否即时生效由生产应用协调器在共享经济写锁中查询可信执行保护事实后决定，不能仅相信外部传入的延期标志。

### ProductionExecution

保证每栋生产建筑最多存在一个未真正结束的生产批次。

批次开始时固定配方、生产方法有效版本和参产人员计划。生产设备系统已移除，工具和机械仍可作为普通商品。

暂停、恢复、完成、提前终止与结算属于受控的生命周期行为。未完成结算的批次不得被覆盖。

执行拥有独立 `executionRevision`。Batch 是内部 Entity：存档只在 `production_batches` 中保存一份可变进度/状态，执行表保存 current/last ID、自动续产、边界、暂停原因和 Tick 标记。Execution 和内部 Batch 在同一 SQLite 事务提交，成功提交才算正式开工。成功保存的 `SETTLING_ABORTED` 不得恢复运行或改变终止进度。

完工或特殊中止时，同一个事务保存库存结算、工资截止、用工释放和批次终态，并进入 `RECONFIGURING`。随后单独应用待生效生产方法，再将批次移入历史。

## 4. 核心领域服务

ProductionRecipeResolver 根据有效方法组合解析不可变配方。

WorkforcePlanningService 根据本批招聘人数和各职业配方需求计算参产计划。每个必需职业至少一人，速度取各职业人数比例的最小值。供给不足可以部分招聘，招聘到的人全部参与生产。

## 5. 与其他上下文的协作

- **Building Identity**：取得建筑身份、类型和运营条件。
- **用工与工资**：读取区域总供给、批次占用和工资状态。开工与终结分别原子取得和释放用工，并变更计薪基数。
- **Inventory & Storage**：整批预留原料、结算消耗和产品入库，并保存幂等结算回执。
- **Company Finance**：不直接持有或修改公司现金；实际工资付款通过 Employment & Compensation 协调。

## 6. 生产业务流程

生产应用服务取得相关权威事实，判断开工条件，在同一事务预留完整原材料、创建批次、取得人员占用并更新计薪人数。

生产进度由 Minecraft 服务端 Tick 事件驱动，满速批次用 200 Tick 完成。每分钟 1200 Tick 用于经济时间换算。推进不依赖客户端界面或建筑区块持续加载，也不补算离线时间。

普通 `stop` 只关闭自动续产，保留当前批次、进度、暂停原因和预留。批次恢复或继续生产至满进度后，消耗全部预留原料并产出完整配方数量，重配置完成后保持停产。空闲时执行 `stop` 会立即关闭自动开工。

欠薪的常规处理是暂停。出售或拆除准备等特殊路径仍可能中止未决定完工的批次。中止结算释放全部预留、零耗料、零产出。

任何跨上下文失败都不能导致重复扣料、重复产出、无主资源锁定或提前释放受保护人员。

活动、暂停或待结算期间，方法变更先保存为待生效请求。结算按旧用工累计工资，保留旧债与余数，再释放人员并清零计薪人数。`RECONFIGURING` 应用生产方法 Pending。本建筑最早在下一经济 Tick 重新开工，重配置未完成时继续阻止开工。

## 7. 非职责范围

Production Operations 不决定公司的采购价格、销售价格、物流路径、资产所有权、工资债务或实际付款。

这些业务由对应上下文承担。生产只表达原材料与劳动力需求以及实际生产结果。

## 8. 存储与运行限制

双聚合使用同一世界 SQLite 和原共享经济写锁；Repository 使用独立 revision 条件更新，加载结果为已验证的独立对象，不另建可变生产 Registry。建筑和两个生产根的首次创建在一个事务完成，失败不发布半初始化建筑。

当前 Schema 为 v12，业务 JSON 为 format 10。运行时使用内存 SQLite 事务，保存时写入完整经济检查点，重启恢复最近成功的检查点。具体调用链和失败恢复见[代码阅读地图](code-reading-map.md)。
